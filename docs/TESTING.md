## 文档校验

`node scripts/generate-docs.mjs --check` 校验最终卡表、基础角色值、等级曲线、原始提交档案及源码/测试/资源摘要是否与生成物一致。生成器有数量保护：21 伙伴、186 唯一卡 ID、每伙伴 5+3；扩展角色时需有意更新此保护。

此检查不证明人工文档每句话正确，也不验证每个 UI 文案与伤害公式完全一致；需代码审阅。source-manifest 的 SHA-256 可证明文档基线与所查源码一致，不是安全签名或资源授权证明。

## 浏览器人工验收

1. 从 Pages 与本地开发分别打开；看版本、资源请求、控制台。WebGL 与软件兼容各记录实际路径。
2. 四方向走路/施法：三月七、黑塔脚底稳定；移动途中技能帧优先；黄泉白发回归；主角和伙伴穿过树，建筑仍阻挡。
3. 拾票 → 召唤：演出开始就有文字；演出前、中、后点击屏幕任意处、背景、按钮、Escape；每次只交付一次固定新角色牌。六人满编新角色仍能收牌。
4. 不召唤直接关闭也给赠礼；全角色已拥有时直接光锥；队内满牌转场下；全角色满牌不扣无用兑换票。
5. 主角池满但队伍未满、队伍全满但主角未满、金卡只剩 1/2/0 张；验证补给、转票、下一层不会卡死。
6. 打开详情、编队、暂停、抽牌时观察所有伤害/计时停止；从编队关闭详情仍暂停。
7. 冻结小怪停止，首领继续移动与预警；杀死发预警的敌人立即消失；异常/碎冰/破韧处决不秒杀首领。
8. 首图接触首领自动开始、杀死自动完成任务；无尽各预算完成出一个首领、奖励后换层；离开/回城保留局内成长。
9. 高密度流萤轰炸/大黑塔扩散/黄泉刀阵观察帧率与遮挡；至少在目标设备记录一段实战。自动数量上限不是帧率保证。
10. 游戏刷新重置是当前设计；不要据此误报存档丢失回归。

## 构建检查

npm run build 检查 Vite 模块/资源解析和 Pages 相对路径；产物在 build。npm run build:local 是独立单文件路径，需要另外验证，不在 npm test 中。没有实际打开本次新生成离线包时不能声称它已实测。
