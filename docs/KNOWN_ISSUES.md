本表记录 v0.9.3 当前状态，不自动授权改玩法。本轮文档重建没有修改下列行为。

| 项目 | 已核对的事实 | 后续处理 |
|---|---|---|
| 每层票券上限翻倍的旧要求 | TRIAL_TICKET_CAP=12，damage 直接比较固定上限；reward-pools 测试也断言 12 | 若要逐层翻倍，另改公式、掉落调用和测试；旧日志说已完成是错误 |
| 全角色拥有后拾票 | 直接发附赠光锥，同时票留在库存，之后还能再花票抽光锥 | 当前测试明确覆盖；需产品判断是否保留双渠道，文档不能擅改成只给一次 |
| 主角自己的牌未满但队伍牌满 | 主角升级直接转票，不弹主角牌 | 这是 teamHasGrowth 的实际条件 |

| 新角色仍有全场/广域能力 | 大黑塔冻结、黄泉异常处决、飞霄牵引等有效 | 属于后续新增要求中的例外，勿按旧全局禁令误删 |
| 波状特效 | 旧黄金重复大波纹已压缩；新角色 fireRing 和部分普通 ring 路径仍存在 | “所有扩散波都不存在”无法成立；改动前区分判定与绘制 |
| 卡牌文案精度 | 最终短文案常不列范围/持续时间，新增卡 II/III 有“效果增强” | 精确参数查代码；目录只记录 UI 文案 |
| 旧分支与数据描述 | data.branches 留存；expansion 的部分旧角色代码被 ascension 提前接管 | 重构可清理，但这轮不删除游戏代码 |
| 原始 Git 历史 | GitHub 是快照导入，旧 SHA 不在远端祖先链 | HISTORY/history.json 保留版本、时间、文件清单；不要伪造远端提交链接 |
| 资源来源 | 存在部分来源元数据，未形成所有资源的完整授权清单 | 逐项核对，不能称“全部已获授权” |
| 本局存档 | 内存状态；刷新/关闭即重置 | 设计存档时要包含牌、队列、地图和版本迁移 |
| 寻路 | 点击目标加简单碰撞移动，没有完整路径规划 | 树可穿过，建筑/湖岸仍可能需绕路 |
| 极高层数 | HP×5、经验×2、间隔不断减半，使用 JS Number 且没有数值上限设计 | 高层精度/溢出/性能未证明安全；有限层测试不是无限稳定性证明 |
| 视觉/设备 | 有软件兼容绘制，非与 WebGL 完全一致；未对所有设备实测 | 分别记录真实浏览器、显卡和帧率结果 |

## 本次纠正的旧文档错误

成长系统首版是 v0.5.0，Combo 是 v0.7.0；初始首领接触唤醒在 v0.6.4，而不是 v0.4；丹恒风刃为八方向起步；25→26 经验是 3000；无尽存活限制为 90，110 属初始营地；首领金卡有场下/补给/车票回退；项目有合成音效。

测试脚本文件名与日志字符串可能保留历史版本名称。通过旧名测试不表示当前行为等于当年版本，也不代表视觉实测。
